# MockAds

## Purpose
A stand-in ad plug for the Ads module: it initializes at once, loads after a set delay and
ends every show the way `CD_MockAds` says, so rewarded and interstitial flows run in the Editor
and in a Development Build before a mediation SDK is in the project.

## Concepts
mock, fake ads, stand-in, placeholder SDK, no SDK yet, development build, rewarded outcome,
dismissed, display failed, no fill, LoadsFail, CD_MockAds, MockAdsProvider

## Using it
1. `AdsServiceRoot` > Sub Context Types > Add > `MockAdsServiceContext`, **AutoSetup** on.
2. Optional: file `Scriptables/CD_MockAds` (or a copy) in `AdsServiceRoot`'s **Shared
   Scriptables**. Without it the mock runs on the class defaults: rewarded earned, loads land
   in 0.5 s, a show lasts 1 s.
3. Change `RewardedOutcome` (`Rewarded`, `Dismissed`, `DisplayFailed`) or `LoadsFail` during Play
   to see each answer the game handles.
4. When the real SDK arrives, replace this entry on the Root with that SDK's plug.

## Decisions
- **Editor and Development Build only.** The provider and the body of the context compile under
  `UNITY_EDITOR || DEVELOPMENT_BUILD`; a release build keeps an empty context, plugs nothing, and
  every ad answers `NotReady` - a mock can never hand out free rewards in a store build.
- **A plug like any other.** It only reports to `IAdsProviderListener`; pacing, retry, timeout and
  the reward decision stay in the Ads module, so what works against the mock works against MAX.
- **Not the test module's fake.** `FakeAdsProvider` answers the test scene's buttons and is
  Editor-only; this one answers by itself, so a game's own scenes and a device build run.
- **Two plugs are not chosen between.** Listed beside a real plug, whichever sets up second is
  refused with the Ads module's error; the decision of which runs stays with the developer.
