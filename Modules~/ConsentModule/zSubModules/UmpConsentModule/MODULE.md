# UmpConsent

## Purpose
The Google UMP plug for the Consent module: the consent form and the privacy options form behind
`IConsentProvider`, compiled only when the Google Mobile Ads package is in the project.

## Concepts
UMP, User Messaging Platform, Google, consent form, privacy options, IAB TCF, TCF string, Recorded,
FLOWIOC_GOOGLE_UMP

## Using it
1. Google Mobile Ads in the project: `com.google.ads.mobile` from OpenUPM, or the
   `.unitypackage` with `FLOWIOC_GOOGLE_UMP` added to Scripting Define Symbols. Its own settings
   take the AdMob app ids, and the consent message is written on the AdMob dashboard.
2. `ConsentServiceRoot` > Sub Context Types > Add > `UmpConsentServiceContext`, AutoSetup on.
3. The game's Connector hands the ad SDKs no consent flag when `IsInTcfString` is set - see the
   Consent card.

## Decisions
- **A form answered is `Recorded`, not `Granted`.** UMP says only that the player answered; what
  they chose, purpose by purpose, is in the IAB TCF string, which MAX and AdMob read on their own.
  A `SetHasUserConsent` handed after it would override that string, so the Consent module reports
  `Recorded` and the Connector hands the ad SDK nothing.
- **The purposes are read back for analytics.** `ReadPurposeConsents` takes
  `IABTCF_PurposeConsents` through GMA's `ApplicationPreferences`, which reads it where UMP wrote
  it on each platform - Android's default SharedPreferences are not Unity's PlayerPrefs.
- **`NotRequired` passes as it is; a form that could not be shown is `Denied`.** Its error is a
  warning; the flow goes on.
- **Answers come back on the main thread they were asked from**, whatever thread UMP calls back on.

## Known gaps
- Compiled against Google Mobile Ads 11.7.0 in FlowIoC-dev on 2026-11-25, and run in the Editor,
  whose UMP client answers `NotRequired`. Not yet run on a phone with a real message.
- No debug geography or test device ids: `ConsentRequestParameters` is sent empty.
